PMHNP clinical toolkit / developer prototype

Clinical Review

Bring visit evidence, symptom review, and medication references into one workspace.

Local demonstration • no external AI • no automatic diagnosis
Prototype scope: The supplied checklist contains six original screening domains, not the DSM-5-TR criteria. Full criteria require an authorized content library and validated diagnostic rules. Use synthetic or de-identified text while developing; this prototype is not validated for patient care.

Diagnoses

Review visit evidence and explore diagnostic possibilities.

Import a visit

Paste text or import a UTF-8 .txt file. Processing stays in this page's memory. Editing text clears prior review.

Keyword extraction is deliberately limited. It does not reliably understand negation, family history, timing, quotations, or clinical meaning. Every hit remains unconfirmed until reviewed.

Review symptom evidence

Check only after reviewing the original statement. A keyword hit is not a clinical finding. Missing evidence remains unknown.

Assessment completeness

These prompts organize follow-up. They do not satisfy diagnosis-specific requirements.

No candidate becomes a confirmed diagnosis in this starter, even when every prompt is checked.

Possibilities to investigate

Triggered by clinician-confirmed screening domains. No probability, DSM threshold count, or treatment recommendation is calculated.

Expandable content library

This starter can load an authorized checklist JSON file. Import replaces the current checklist and clears visit review; no text is sent to a server. The current matcher accepts literal phrases, not executable rules.

Production work still needed

  • Licensed DSM-5-TR content, versioning, copyright notices, and diagnosis-specific rules reviewed by clinicians.
  • Validated extraction for patient vs. family history, current vs. historical symptoms, negation, frequency, severity, contradictions, and source evidence offsets.
  • Duration, required symptom groups, functional impact, exclusions, specifiers, developmental context, and differential comparisons.
  • Medication catalog by ingredient, product, route, release formulation, indication, age, tablet strength, and source revision; explicit off-label status.
  • Patient-specific prescribing checks, monitoring, allergies, interactions, organ function, pregnancy, and clinical sign-off.
  • Approved patient-data environment, access control, encryption, audit history, retention rules, and appropriate vendor agreements before identifiable visits.

No patient data belongs in GitHub source, issues, logs, or test fixtures. This file makes no network requests and uses no browser persistence. Exported review files can contain visit text.
